# Как организую работу над продуктом

Артемий Бражников. Рабочий подход, применяемый с Codex и Claude Code. Опыт подтверждается отдельными [кейсами](https://artemarzi.github.io/portfolio/projects/); этот документ не означает завершённости всех продуктов.

## 1. Процесс и задача

Сначала разбираюсь, кто выполняет работу, где приходят данные, какие правила действуют и какой результат нужен. На строительном проекте встречался с заказчиком и уточнял процесс; в клубе сам занимался операционкой, лидами, оплатами и выплатами.

## 2. Требования и границы

Фиксирую пользователей, основной сценарий, ошибочные ситуации и критерии готовности. Разделяю разные сущности: например, оплату, посещение и расчёт выплаты. Отдельно определяю, где нужны подтверждение человека и данные внешней системы.

## 3. Реализация

Изучаю репозиторий и архитектуру, затем собираю решение по частям. Codex и Claude Code помогают с кодом и исследованием; выбор решения, постановку задачи и проверку результата сохраняю за собой.

## 4. Проверки

Проверяю тот сценарий, который будет использовать человек, и существенные ошибки вокруг него: неверные параметры, повтор сообщения, конфликт состояния и отказ интеграции. Для интерфейсов смотрю реальные экраны на desktop и мобильном размере. У каждой проверки есть граница: unit-тест не доказывает доставку Telegram или успешный реальный платёж.

## 5. Внедрение и передача

Рабочие решения внедряю поэтапно. Оставляю описание устройства, команды запуска и проверки, ограничения и следующие шаги. Учитываю обратную связь пользователей. В клубе отдельный бот решает ежедневную задачу, пока внедрение большого продукта продолжается.
